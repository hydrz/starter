# ADR-0002：生产数据库只向前迁移

- 状态：已接受
- 日期：2026-09-24

## 背景

数据库 schema 与已经发布的应用版本共同构成生产状态。直接回滚 migration 可能删除新版本已经写入的数据，也可能使仍在运行的实例失去所需字段。

## 决策

- 已进入共享或生产环境的 migration 永不修改；
- 生产故障通过新的修复 migration 向前恢复，不自动执行 Goose `down`；
- 每个 migration 仍提供 `Down`，仅用于合并前的本地和 CI 往返验证；
- 删除列、修改类型等破坏性操作采用 expand/contract 分阶段实施；
- migration 与依赖它的应用代码必须在同一个 Pull Request 中评审。

## 结果

生产恢复过程更可预测，并避免回滚造成二次数据损失。代价是 schema 修复需要新增 migration，团队必须提前设计兼容多个应用版本的过渡状态。
