# ADR-0007：PostgreSQL outbox 与进程内 worker

- 状态：已接受
- 日期：2026-09-26
- 决策者：Architecture
- 被替代：无

## 背景

身份通知、邮件交付和 Stripe webhook 后处理必须在数据库状态改变后可靠执行。数据库提交后直接做网络调用会在进程崩溃、超时和重试中产生丢失或重复副作用；同时项目约束要求继续交付一个 Go 二进制。

## 决策

使用 PostgreSQL outbox。业务事务同时写入领域状态和 outbox 事件。单个 Go 进程内的受限 worker 定期批量 claim 可处理行，执行 handler，并记录成功、失败、重试时间和幂等信息。使用 PostgreSQL 锁定/claim 语义保证多实例部署不会重复持有同一工作；外部调用仍按至少一次语义设计并使用供应商/业务幂等键。

worker 配置以 `WORKER_ENABLED` 显式开启，默认轮询间隔为一秒、批量大小为 50。它不在本阶段运行，也不替代更大规模时可另行评估的专用队列。

## 备选方案

### 事务内同步网络调用

不能原子地协调数据库与外部系统，增加请求延迟，失败恢复困难，未选择。

### 立即引入独立队列和独立 worker 服务

当前规模增加运维与部署拓扑，违反单 Go 二进制约束，未选择。

## 结果

获得可靠且与当前 PostgreSQL/pgxpool/Goose/sqlc 栈一致的异步边界，代价是 outbox schema、claim 协议、重试观测和幂等测试。delivery 是 outbox 的一个消费者，不是其唯一用途。

Limen 的公开可靠性边界是设计影响来源；本仓库不复制其代码。
