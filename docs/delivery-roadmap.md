# 分阶段实施路线

## 实施规则

- 每次只交付一个可独立评审的部分；
- 当前部分经确认后，才进入下一部分；
- 每部分必须同时包含实现、文档与可执行验证；
- 新增工具必须有明确用途、固定版本和统一的 pnpm script 入口；
- 对不可逆或影响团队协作的选择使用 ADR 记录。

## 阶段状态说明

路线图中的各阶段交付状态遵循以下枚举定义：

| 状态 | 含义 | 流转条件 |
| --- | --- | --- |
| **`待规划`** | 仅有高阶目标，尚未进入详细方案设计与任务拆解。 | 需求提出，等待排期。 |
| **`进行中`** | 方案已确认，正处于实现、测试与联调闭环过程中。 | 当前唯一活跃推进的阶段。 |
| **`已完成`** | 已完成代码实现、全量自动化验证、文档固化并合并主干。 | 验收准则全部满足并通过审查。 |
| **`已延后`** | 因优先级调整或前置外部依赖缺失而暂缓执行。 | 经技术决策委员会确认后标记，保留背景说明。 |
